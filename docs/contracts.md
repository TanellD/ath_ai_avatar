# Контракты данных

Реализация Claude.md §7. Единственный источник истины —
[`packages/contracts/`](../packages/contracts/); сервисы не объявляют своих
копий этих моделей.

TypeScript-зеркало (`services/frontend/src/contracts/events.ts`) пока написано
руками. Сгенерировать из JSON Schema:

```powershell
.\scripts\gen-ts-contracts.ps1
```

## Почему общий пакет, а не «договорились по традиции»

В референсном `tatarby-main` форма JSON между Node-бэкендом и Python-сервисом
распознавания согласована только тем, что обе стороны написаны одним человеком.
Никакой проверки нет: `transcriber.ts` ждёт `{transcription}`, а
`emotions-parser/app.py` возвращает это поле — до тех пор, пока кто-нибудь его
не переименует.

Здесь контракт — устанавливаемый пакет, и рассинхрон ловится импортом.

## События WebSocket

### Клиент → сервер

| Событие | Поля | Комментарий |
|---|---|---|
| `user_message` | `text`, `interrupts` | Отправка = перебивание. Клиент уже остановил звук локально |
| `ping` | — | Keep-alive |

`[STT]` В §7 на месте одного `user_message` стоят три события:
`speech_start` / `user_audio` / `speech_end`. Они объявлены закомментированными
в `events.py` и включаются вместе с голосом — см. [stt-phase.md](stt-phase.md).
`user_message` при этом остаётся: он и рабочий путь, и готовый fallback.

### Сервер → клиент

Полный набор из §7, без изменений — ни одно из этих событий не зависит от
способа ввода.

| Событие | Поля | Комментарий |
|---|---|---|
| `token` | `gen_id`, `text` | Для субтитров и лога, **не для тайминга** |
| `audio_chunk` | `gen_id`, `seq`, `data`, `format`, `emotion` | По порядку; `emotion` синхронизирует лицо с озвучиваемым поколением |
| `subtitle` | `gen_id`, `text`, `start_ms`, `end_ms` | Тайминги относительно начала аудио **поколения** |
| `transcript` | `gen_id`, `text`, `is_final`, `stt_confidence` | `[STT]` Объявлено, не эмитится |
| `action` | `gen_id`, `action`, `stage_id` | `stay` / `next_stage` / `finish` / `evaluate` |
| `cancel` | `gen_id` | Отменяемое поколение |
| `report` | `session_id`, отчёт | Один раз в конце |
| `error` | `gen_id`, `code`, `message` | Ошибка, понятная пользователю |

**Инвариант:** каждое событие сервер → клиент несёт `gen_id`, и клиент
отбрасывает всё с `gen_id != current`. Исключение — `cancel`: он по определению
говорит о поколении, которое уже не текущее.

## Поля, которые всегда `None` в этой фазе

`Turn.stt_confidence`, `Turn.audio_ref`, `CriterionScore.audio_ref`,
`CriterionScore.stt_confidence`.

Объявлены заранее намеренно. При текстовом вводе транскрипт есть истина, и
подтверждать цитату записью не нужно; при голосовом — станет необходимо, и
контракт отчёта от этого не сломается. Соответствующие колонки в БД тоже уже
заведены, так что миграции с переносом данных не понадобится.

## Одно поле, на котором держится продукт

`CriterionScore.evidence` — дословная цитата из реплики сотрудника,
обязательная и непустая под каждым баллом.

Без неё методист не может проверить оценку быстро, начнёт перечитывать историю
целиком, и экономия времени исчезнет. Это главная гипотеза проекта (§7), а не
деталь оформления — поэтому проверка стоит не только в промпте, но и в коде:
`ai-service/app/evaluation/report_builder.py` отбраковывает отчёт, если цитата
не встречается в репликах сотрудника дословно.

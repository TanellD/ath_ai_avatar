# Контекст проекта: цифровой тренажёр корпоративных тренировок

Файл для ИИ-агентов разработки. Читать перед любой задачей по коду.

---

## 1. Что строим

Веб-приложение, в котором сотрудник проходит тренировочный диалог с говорящим персонажем по заданному сценарию. Методист получает историю разговора и итоговую оценку.

Типы тренировок: собеседование, продажи, отработка возражений, проверка знаний.

**Ключевое отличие от чат-ассистента: инициативу держит агент.** Он спрашивает, ведёт по этапам, дожимает неполные ответы и завершает сессию оценкой. Пользователь не задаёт вопросы — он на них отвечает.

## 2. Пользователи

Их двое, по постановке кейса.

| Роль | Что делает в системе |
|---|---|
| **Методист** | Выбирает или настраивает сценарий, задаёт критерии оценки. После сессии получает историю разговора и итоговую оценку |
| **Сотрудник** | Проходит диалог с персонажем |

Отдельной роли администратора или руководителя не делаем — в кейсе её нет.

**Отчёт — это интерфейс методиста, и он главный.** Каждый балл обязан быть проверяем за десять секунд, иначе методист начнёт слушать записи целиком и продукт потеряет смысл.

## 3. Жёсткие ограничения

Из условий кейса. Нарушение = провал приёмки.

- Реальная LLM, не заготовленные ответы
- Агент хранит состояние и имеет минимум одно действие: перейти к этапу / завершить / сформировать оценку
- **Каждый ответ имеет `gen_id`. После отмены старые аудио, субтитры и кадры мимики отбрасываются**
- **Источник времени для мимики — фактически воспроизводимое аудио, а не независимый таймер.** Никаких `setInterval`, только `AudioContext.currentTime` или `HTMLAudioElement.currentTime`
- TTS озвучивает ответ по частям, пользователь не ждёт генерации целиком
- Голос и изображение реального человека без согласия не используются
- Проект запускается локально по инструкции команды

## 4. Не входит в скоуп

- **Голосовой ввод и распознавание речи.** Ввод только текстовый. Не добавлять STT, VAD, barge-in по звуку
- Фотореалистичный персонаж, клонирование голоса
- Обучение своих моделей
- Большая база знаний и сложный RAG (допустим простейший поиск по короткому документу)
- Телефония, CRM, интеграции
- Многопользовательская нагрузка, авторизация уровня энтерпрайза
- Локальный инференс. Все модели — по API

## 5. Архитектура

```
user text
  → orchestrator (состояние сценария, gen_id)
    → LLM stream (реплика персонажа + action)
      → sentence splitter
        → TTS stream (чанки аудио)
          → client: audio playback = единственные часы
            → lip-sync (от currentTime аудио)
            → subtitles (от currentTime аудио)
```

Оркестратор — сервер. Клиент только воспроизводит и рисует.

### Разделение моделей

- **Реплики персонажа** — быстрая дешёвая модель. Приоритет: time to first token. Ум не важен, глубоких бесед нет (прямая вводная заказчика)
- **Итоговая оценка** — сильная модель, один вызов после завершения. Структурированный JSON, обязательная цитата под каждым баллом

### Управление этапами

Конечный автомат. LLM **не** решает свободно, куда двигаться — она классифицирует ответ пользователя как `complete | incomplete | off_topic`, переход делает код.

Причина: требование заказчика не отходить от методики. Свободная навигация даёт 20–30% преждевременных переходов.

### Контекст

Скользящее окно: полный текст последних 6 ходов + сжатая выжимка остального. Иначе стоимость диалога растёт квадратично.

## 6. Протокол отмены

Единственное место, где ошибка гарантированно убивает демо.

1. Клиент отправляет `user_message`
2. Сервер инкрементирует счётчик поколений, выдаёт новый `gen_id`
3. Сервер отменяет активные LLM- и TTS-стримы (`AbortController`)
4. Сервер шлёт `cancel {gen_id: old}`
5. Клиент немедленно: `audio.pause()`, очистка очереди буферов, сброс кадров мимики, фиксация субтитров на текущей позиции
6. **Все события несут `gen_id`. Клиент отбрасывает любое событие с `gen_id != current`**

Инвариант: после отмены ни один чанк старого поколения не воспроизводится. Ноль возвратов — не цель, а требование.

Ввод текстовый, поэтому отмена детерминирована: событие — нажатие Enter, порогов и ложных срабатываний нет.

## 7. Контракты данных

### Сценарий

Создаётся методистом: из шаблона, из сгенерированного черновика или с нуля.

```json
{
  "id": "objection_price",
  "title": "Отработка возражения «дорого»",
  "persona": {
    "name": "Ирина",
    "role": "закупщик среднего бизнеса",
    "character": "скептична, перебивает, торгуется",
    "mood": "neutral | irritated | friendly",
    "difficulty": 1,
    "voice_id": "..."
  },
  "stages": [
    {
      "id": "opening",
      "goal": "Установить контакт и выяснить контекст",
      "agent_opening": "Здравствуйте. У меня десять минут, давайте по делу.",
      "completion_criteria": "Сотрудник представился и задал минимум один открытый вопрос",
      "max_turns": 4
    }
  ],
  "rubric": [
    {
      "id": "discovery",
      "name": "Выявление потребности",
      "description": "Задавал открытые вопросы, не перешёл к презентации раньше времени",
      "scale": 5,
      "weight": 1.0
    }
  ]
}
```

`persona.mood` и `difficulty` варьируются между прогонами одного сценария — ответ на главную жалобу пользователей аналогов (предсказуемость бота).

### Состояние сессии

```json
{
  "session_id": "uuid",
  "scenario_id": "objection_price",
  "current_stage": "discovery",
  "current_gen": 7,
  "turns": [{"role": "user|agent", "text": "...", "stage_id": "...", "ts": 0}],
  "stage_history": [{"stage_id": "opening", "turns_spent": 3, "exit": "complete"}],
  "status": "active | finished | abandoned"
}
```

### События (WebSocket, сервер → клиент)

| Событие | Поля | Комментарий |
|---|---|---|
| `token` | `gen_id`, `text` | Для субтитров и лога, не для тайминга |
| `audio_chunk` | `gen_id`, `seq`, `data`, `format` | По порядку, клиент буферизует |
| `subtitle` | `gen_id`, `text`, `start_ms`, `end_ms` | Тайминги относительно начала аудио поколения |
| `action` | `gen_id`, `action`, `stage_id` | `stay` / `next_stage` / `finish` / `evaluate` |
| `cancel` | `gen_id` | Отменяемое поколение |
| `report` | `session_id`, отчёт | Один раз в конце |

### Отчёт методисту

```json
{
  "session_id": "uuid",
  "verdict": "Уверенно ведёт выявление, теряется на возражении по цене",
  "total_score": 3.4,
  "scores": [
    {
      "criterion_id": "discovery",
      "score": 4,
      "evidence": "«А сколько сейчас тратите на это в месяц?»",
      "comment": "Задал открытый вопрос до презентации"
    }
  ],
  "transcript": [],
  "duration_sec": 480,
  "stages_completed": 4,
  "stages_total": 4
}
```

**Каждый балл обязан иметь `evidence` — дословную цитату из реплики пользователя.** Без неё методист не может проверить оценку быстро, начнёт слушать запись целиком, и экономия времени исчезнет. Это главная гипотеза проекта, а не деталь оформления.

## 8. Требования к клиенту

- Мимика и субтитры считываются **только** из `currentTime` воспроизводимого аудио
- Первый звук стартует до окончания генерации всего ответа
- При деградации сети: лицо замирает, голос продолжается. Не наоборот
- Поле ввода активно во время речи персонажа — перебивание должно быть возможно всегда
- Экран методиста после сессии: история разговора, оценка по критериям с цитатами, счётчик освобождённых часов

## 9. Приёмочные метрики

| № | Метрика | Порог | Цель |
|---|---|---|---|
| 1 | Time to first audio, p95 | ≤ 3.0 с | ≤ 1.5 с |
| 2 | Смещение аудио и губ | ≤ 200 мс | звук не опережает губы >45 мс, не отстаёт >125 мс |
| 3 | Время остановки при перебивании | ≤ 300 мс | ≤ 150 мс |
| 4 | Возвраты отменённого хвоста | **0** | 0 |
| 5 | Корректно завершённые сценарии | ≥ 4 из 5 | 5 из 5 |
| 6 | Себестоимость минуты | посчитана | ≤ 10 ₽ |

Не путать: **3 с** — до первого звука, **300 мс** — на остановку при перебивании. Разные метрики.

Порог липсинка асимметричен (ITU-R BT.1359): опережение звука заметно примерно вдвое раньше отставания. Лучше отдать лицо чуть раньше звука, чем позже.

### Бюджет задержки

| Этап | Бюджет |
|---|---|
| LLM: первый токен | 300–800 мс |
| TTS: первый чанк | 150–400 мс |
| Сеть и буфер клиента | 100–200 мс |
| **Итого** | **0.55–1.4 с** |

STT и VAD в бюджете отсутствуют: ввод текстовый.

## 10. Технические решения

- **Рендер лица:** Simli (audio→video, managed, ~$0,009/мин, отдаёт чистый API). Запасной вариант для демо без интернета — bitHuman (локально, CPU). Проверить статус SDK: репозиторий переведён в read-only
- **Не брать:** HeyGen LiveAvatar (латентность 1–2 с, проваливает метрику 1), MuseTalk (высокий риск, русского нет в заявленных языках). Tavus — только рендер, его Raven и Sparrow дублируют наш оркестратор
- **Разбиение для TTS:** по предложениям, первое отправляется сразу, не дожидаясь конца генерации
- **Хранение:** сессии и отчёты в БД с первого дня — нужны для истории методисту и для аналитики

## 11. Definition of done для демо

Пять минут, вживую, без записи:

1. Методист выбирает шаблон, меняет два поля, запускает — за минуту
2. Сотрудник проходит диалог: быстрый старт звука, губы за аудио, субтитры не убегают
3. Перебить посреди фразы 2–3 раза: речь встаёт, хвост не возвращается, персонаж отвечает на новую реплику
4. Прогнать тот же сценарий второй раз — персонаж возражает иначе
5. Показать отчёт методисту: история разговора, баллы, цитата под каждым баллом
6. Показать счётчик освобождённых часов

Прогнать на чужом вайфае и через проектор до защиты.

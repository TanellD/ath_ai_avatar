# Roadmap: Now / Next / Later

Три горизонта разного типа. **Now** — что уже реализовано в MVP. **Next** —
известные пробелы того же MVP; закрыть их важнее, чем добавлять
функциональность. **Later** — расширение продукта после пилота, включая
поиск по базе знаний методиста.

## Now — реализовано

Выбор и редактор сценариев, диалог с учётом состояния и истории (текст и
голос), поэтапное озвучивание без ожидания полного ответа, говорящий
3D-персонаж с мимикой по реальному аудиопотоку, субтитры, прерывание речи
новой репликой, гарантированное отбрасывание устаревшего ответа при
перебивании, итоговый отчёт с баллами и дословными цитатами, автогенерация
сценария методистом по краткому описанию.

## Next — закрыть известные пробелы, не наращивать функциональность

| Пробел | Почему важнее новых фич |
|---|---|
| Мгновенное распознавание начала речи для перебивания (сейчас — удержание кнопки записи, а не голос поверх персонажа без нажатий) | Целевой UX — перебить голосом в любой момент без действия руками; текущая реализация этого не даёт |
| Хранение аудио сотрудника и voice-фрагмента под цитатой в отчёте | Это ядро гипотезы «десятисекундная проверка цитаты» — без прослушивания фрагмента при ошибках распознавания речи цитату нечем перепроверить |
| Точность классификатора этапов диалога («ответ полный / неполный / не по теме») не измерена на размеченной выборке | От неё зависит, не переходит ли автомат этапов преждевременно — риск для всей механики сценария |
| Пересчёт себестоимости под облачного LLM-провайдера при иной конфигурации, не только под собственную инфраструктуру | Тарифная сетка сейчас опирается на себестоимость собственной инфраструктуры |
| Пилот с реальными методистами: доверие к оценке без правок, completion rate, время проверки отчёта | Главная продуктовая гипотеза не подтверждена и не опровергнута — это открытый риск продукта, а не техдолг |

## Later — расширение после пилота

**Поиск по базе знаний методиста (RAG).** Встраивается в архитектуру в двух
разных местах, с разной ценой:

- *Реплики персонажа* — короткий поиск по документу компании (прайс, скрипт,
  политика) перед генерацией реплики, чтобы возражения звучали с реальными
  фактами клиента, а не выдуманными. Конфликтует с бюджетом задержки: реплики
  персонажа намеренно генерируются быстрой дешёвой моделью ради скорости
  первого звука, а поиск-перед-генерацией эту скорость ест. Ограничиться
  простым поиском по короткому документу с кэшем на старте сессии, а не
  полным пайплайном поиска на каждый ход.
- *Оценка (rubric)* — задержка не критична, это один вызов после завершения
  сессии. Модель оценки сверяет ответ сотрудника не с абстрактным критерием, а
  с конкретным пунктом корпоративного стандарта из базы методиста — усиливает
  доказательность цитаты в отчёте. Менее рискованное и более ценное место для
  такого поиска, чем реплики персонажа.

Коммерчески это — ось перехода между тарифами: настройка под клиентскую базу
знаний требует индивидуального внедрения, а не бесплатная фича входа.

**Остальное после этого, без обязательного порядка внутри списка:**

- Библиотека готовых сценариев по индустриям — снижает время до первой
  ценности для нового клиента.
- Командная аналитика для методиста: тренды по критериям рубрики за период,
  а не только единичный отчёт.
- Мультиязычность распознавания и синтеза речи.
- Интеграции с корпоративными системами обучения (СДО/LMS) — рынок уже
  ожидает это как норму у сопоставимых российских продуктов.
- Персонализированный план развития — агрегация слабых критериев рубрики по
  сотруднику через несколько сессий.

## Явно не планируется

Фотореалистичный видеоперсонаж, клонирование голоса, обучение собственных
моделей, телефония/CRM/промышленные интеграции, локальный инференс
распознавания речи — если не появится отдельное решение это пересмотреть.

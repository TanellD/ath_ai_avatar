# CLAUDE.md — Контекст проекта: цифровой тренажёр корпоративных тренировок

Файл для Claude Code. Читать перед любой задачей по коду.

> **Главное изменение относительно первой версии постановки: ввод — голосовой, через STT-модуль.**
> Сотрудник **говорит**, а не печатает. Это не косметика: меняются протокол отмены (§6), бюджет задержки (§9), «толщина» клиента (§5, §8) и — важнее всего — способ проверки цитат в отчёте (§7). Все затронутые места помечены `[STT]`.

---

## 1. Что строим

Веб-приложение, в котором сотрудник проходит тренировочный диалог с говорящим персонажем по заданному сценарию. Методист получает историю разговора и итоговую оценку.

Типы тренировок: собеседование, продажи, отработка возражений, проверка знаний.

**Ключевое отличие от чат-ассистента: инициативу держит агент.** Он спрашивает, ведёт по этапам, дожимает неполные ответы и завершает сессию оценкой. Пользователь не задаёт вопросы — он на них отвечает.

**`[STT]` Ввод — голосовой.** Речь сотрудника захватывается микрофоном, VAD на клиенте детектирует начало/конец реплики, потоковый STT по API превращает её в текст, дальше — существующий конвейер. Перебивание персонажа теперь голосовое (barge-in), а не нажатием Enter. Диалог стал по-настоящему устным в обе стороны — это и есть цель, ради которой стоило усложнение.

## 2. Пользователи

Их двое, по постановке кейса.

| Роль | Что делает в системе |
|---|---|
| **Методист** | Выбирает или настраивает сценарий, задаёт критерии оценки. После сессии получает историю разговора и итоговую оценку |
| **Сотрудник** | Проходит диалог с персонажем (голосом) |

Отдельной роли администратора или руководителя не делаем — в кейсе её нет.

**Отчёт — это интерфейс методиста, и он главный.** Каждый балл обязан быть проверяем за десять секунд, иначе методист начнёт слушать записи целиком и продукт потеряет смысл.

## 3. Жёсткие ограничения

Из условий кейса. Нарушение = провал приёмки.

- Реальная LLM, не заготовленные ответы
- Агент хранит состояние и имеет минимум одно действие: перейти к этапу / завершить / сформировать оценку
- **Каждый ответ имеет `gen_id`. После отмены старые аудио, субтитры и кадры мимики отбрасываются**
- **Источник времени для мимики — фактически воспроизводимое аудио, а не независимый таймер.** Никаких `setInterval`, только `AudioContext.currentTime` или `HTMLAudioElement.currentTime`
- TTS озвучивает ответ по частям, пользователь не ждёт генерации целиком
- **`[STT]` Ввод — потоковый STT по API. VAD — на клиенте, чтобы barge-in срабатывал без сетевого round-trip. STT-инференс — только по API (локальный инференс вне скоупа)**
- **`[STT]` Обязательно эхоподавление (AEC): микрофон не должен слышать собственный голос персонажа из колонок и перебивать сам себя. Резервный вариант для демо — наушники**
- Голос и изображение реального человека без согласия не используются. **`[STT]` Голос сотрудника мы записываем и частично храним (см. §7, §10) — участие в тренинге является согласием, но фиксируем это в UI**
- Проект запускается локально по инструкции команды

## 4. Не входит в скоуп
- Фотореалистичный персонаж, клонирование голоса
- Обучение своих моделей
- Большая база знаний и сложный RAG (допустим простейший поиск по короткому документу)
- Телефония, CRM, интеграции
- Многопользовательская нагрузка, авторизация уровня энтерпрайза
- Локальный инференс. Все модели — по API (**`[STT]` включая STT; VAD — исключение, лёгкий клиентский компонент, не «модель»**)

## 5. Архитектура

```
mic capture (client)
  → VAD (client) ── onset ──► barge-in: локальная остановка воспроизведения
      │
      └─ speech frames → server → STT stream (API) → text
                                                       │
  user text ◄──────────────────────────────────────────┘
    → orchestrator (состояние сценария, gen_id)
      → LLM stream (реплика персонажа + action)
        → sentence splitter
          → TTS stream (чанки аудио)
            → client: audio playback = единственные часы
              → lip-sync (от currentTime аудио)
              → subtitles (от currentTime аудио)
```

Оркестратор — сервер. **`[STT]` Клиент раньше «только воспроизводил и рисовал»; теперь он ещё захватывает микрофон, крутит VAD и стримит аудио на сервер. Но логики сценария в клиенте по-прежнему нет — VAD принимает ровно одно решение (говорит человек или нет), всё остальное решает сервер.**

**`[STT]` Где что живёт (важное разделение):**
- **VAD — на клиенте.** Barge-in обязан останавливать звук за <300 мс (метрика 3); ждать ответа сервера нельзя. Onset речи → клиент сам, локально, ставит `audio.pause()`.
- **STT — по API, аудио маршрутизируется через сервер.** Так оркестратор владеет `gen_id` и корреляцией, а ключи STT не уезжают на клиент. Партиалы транскрипта можно отдавать в лог/субтитры до финализации.

### Разделение моделей

- **Реплики персонажа** — быстрая дешёвая модель. Приоритет: time to first token. Ум не важен, глубоких бесед нет (прямая вводная заказчика)
- **`[STT]` STT** — потоковая модель по API, приоритет: низкая латентность финализации и качество на русском + доменной лексике (цены, названия). Ошибки STT напрямую бьют по цитатам в отчёте — см. §7
- **Итоговая оценка** — сильная модель, один вызов после завершения. Структурированный JSON, обязательная цитата под каждым баллом

### Управление этапами

Конечный автомат. LLM **не** решает свободно, куда двигаться — она классифицирует ответ пользователя как `complete | incomplete | off_topic`, переход делает код.

Причина: требование заказчика не отходить от методики. Свободная навигация даёт 20–30% преждевременных переходов.

### Контекст

Скользящее окно: полный текст последних 6 ходов + сжатая выжимка остального. Иначе стоимость диалога растёт квадратично.

## 6. Протокол отмены `[STT]` — переписан под barge-in

Единственное место, где ошибка гарантированно убивает демо.

**Что изменилось.** При текстовом вводе отмена была детерминирована: событие — нажатие Enter, порогов и ложных срабатываний нет. С голосом триггер отмены — VAD, у него есть порог и возможны ложные срабатывания. **Механизм отмены ниже триггера (gen_id → abort → отбрасывание) не меняется вообще — он не зависит от способа ввода. Меняется только событие, которое его запускает, и добавляется локальная мгновенная остановка на клиенте.**

Последовательность при перебивании:

1. **Клиент, VAD, onset речи → немедленно и локально:** `audio.pause()`, очистка очереди буферов, сброс кадров мимики, фиксация субтитров на текущей позиции. **Без сетевого round-trip** — именно это укладывается в метрику 3.
2. Клиент шлёт `speech_start {interrupts: gen_id_old}` и начинает стримить `user_audio`.
3. Сервер инкрементирует счётчик поколений, выдаёт новый `gen_id`.
4. Сервер отменяет активные LLM- и TTS-стримы (`AbortController`).
5. Сервер шлёт `cancel {gen_id: old}` (для клиентов/логики, которые ещё не знают о новом поколении).
6. Клиент по `speech_end` (VAD endpoint) даёт STT финализироваться; финальный транскрипт уходит в оркестратор как новая реплика.
7. **Все события несут `gen_id`. Клиент отбрасывает любое событие с `gen_id != current`.**

**Два разных класса сбоев — не путать:**
- **Возврат отменённого хвоста** (метрика 4 = **0**) — жёсткий инвариант, держится через `gen_id`. Даже ложное срабатывание VAD его не нарушает: в худшем случае звук зря остановился, но старый чанк не воспроизведётся.
- **Ложный barge-in** (VAD сработал на кашель, «угу», эхо персонажа) — это UX-баг, не нарушение инварианта. Митигируем: AEC + наушники на демо, минимальная длительность речи для подтверждения onset (2–3 фрейма), не реагируем на короткий бэкченел.

**Инвариант:** после отмены ни один чанк старого поколения не воспроизводится. Ноль возвратов — не цель, а требование.

**Консервативный запасной режим (если AEC/эхо капризничают перед защитой):** push-to-talk — сотрудник удерживает клавишу/кнопку, пока говорит. Это возвращает детерминизм текстового ввода (явный сигнал начала/конца, нет ложных срабатываний) ценой естественности. Держим как fallback по аналогии с Simli → bitHuman.

## 7. Контракты данных

### Сценарий

Создаётся методистом: из шаблона, из сгенерированного черновика или с нуля.

```json
{
  "id": "objection_price",
  "title": "Отработка возражения «дорого»",
  "persona": {
    "name": "Ирина",
    "role": "закупщик среднего бизнеса",
    "character": "скептична, перебивает, торгуется",
    "mood": "neutral | irritated | friendly",
    "difficulty": 1,
    "voice_id": "..."
  },
  "stages": [
    {
      "id": "opening",
      "goal": "Установить контакт и выяснить контекст",
      "agent_opening": "Здравствуйте. У меня десять минут, давайте по делу.",
      "completion_criteria": "Сотрудник представился и задал минимум один открытый вопрос",
      "max_turns": 4
    }
  ],
  "rubric": [
    {
      "id": "discovery",
      "name": "Выявление потребности",
      "description": "Задавал открытые вопросы, не перешёл к презентации раньше времени",
      "scale": 5,
      "weight": 1.0
    }
  ]
}
```

`persona.mood` и `difficulty` варьируются между прогонами одного сценария — ответ на главную жалобу пользователей аналогов (предсказуемость бота).

### Состояние сессии

```json
{
  "session_id": "uuid",
  "scenario_id": "objection_price",
  "current_stage": "discovery",
  "current_gen": 7,
  "turns": [{"role": "user|agent", "text": "...", "stage_id": "...", "ts": 0, "stt_confidence": 0.0, "audio_ref": null}],
  "stage_history": [{"stage_id": "opening", "turns_spent": 3, "exit": "complete"}],
  "status": "active | finished | abandoned"
}
```

`[STT]` У ходов пользователя `text` — это выход STT (не истина в последней инстанции). `stt_confidence` и `audio_ref` (указатель на сохранённый сегмент аудио) нужны, чтобы отчёт остался проверяемым — см. ниже.

### `[STT]` События клиент → сервер (WebSocket)

| Событие | Поля | Комментарий |
|---|---|---|
| `speech_start` | `interrupts` (gen_id или null) | Onset речи от VAD. Клиент к этому моменту УЖЕ локально остановил воспроизведение |
| `user_audio` | `seq`, `data`, `format` | Бинарные чанки речи, по порядку |
| `speech_end` | — | VAD endpoint. Сигнал STT финализировать транскрипт |

### События сервер → клиент (WebSocket)

| Событие | Поля | Комментарий |
|---|---|---|
| `token` | `gen_id`, `text` | Для субтитров и лога, не для тайминга |
| `audio_chunk` | `gen_id`, `seq`, `data`, `format` | По порядку, клиент буферизует |
| `subtitle` | `gen_id`, `text`, `start_ms`, `end_ms` | Тайминги относительно начала аудио поколения |
| `transcript` | `gen_id`, `text`, `is_final`, `stt_confidence` | `[STT]` Партиалы и финал распознавания реплики пользователя |
| `action` | `gen_id`, `action`, `stage_id` | `stay` / `next_stage` / `finish` / `evaluate` |
| `cancel` | `gen_id` | Отменяемое поколение |
| `report` | `session_id`, отчёт | Один раз в конце |

### Отчёт методисту

```json
{
  "session_id": "uuid",
  "verdict": "Уверенно ведёт выявление, теряется на возражении по цене",
  "total_score": 3.4,
  "scores": [
    {
      "criterion_id": "discovery",
      "score": 4,
      "evidence": "«А сколько сейчас тратите на это в месяц?»",
      "audio_ref": {"turn": 5, "start_ms": 1200, "end_ms": 3800},
      "stt_confidence": 0.94,
      "comment": "Задал открытый вопрос до презентации"
    }
  ],
  "transcript": [],
  "duration_sec": 480,
  "stages_completed": 4,
  "stages_total": 4
}
```

**Каждый балл обязан иметь `evidence` — дословную цитату из реплики пользователя.** Без неё методист не может проверить оценку быстро, начнёт слушать запись целиком, и экономия времени исчезнет. Это главная гипотеза проекта, а не деталь оформления.

**`[STT]` Как голосовой ввод бьёт по этой гипотезе — и что с этим делаем.**
При текстовом вводе транскрипт был истиной: цитата = ровно то, что напечатал человек. Теперь `evidence` — это цитата из **STT-транскрипта**, который может ошибиться на именах, числах, ценах — то есть ровно на том, что чаще всего и есть содержание балла. Методист прочтёт цитату, она не сойдётся с тем, что реально сказали, и десятисекундная проверяемость сломается — а это ядро продукта.

Поэтому:
- Каждая `evidence` несёт `audio_ref` — короткий (≈5 с) фрагмент исходного аудио. Методист жмёт и слушает **только эту фразу**, не всю запись. Проверяемость восстановлена даже при ошибке STT.
- `stt_confidence` под цитатой: низкая уверенность — визуальный флаг «перепроверь на слух».
- Модель оценки цитирует **строго из транскрипта, дословно** (додумывать нельзя). Любое расхождение — это транскрипционная ошибка, и она вскрывается воспроизведением фрагмента, а не переписыванием цитаты.

Это не отменяет тезис «методисту не нужно слушать запись целиком»: точечное прослушивание одной фразы — другое действие, оно быстрое.

## 8. Требования к клиенту

- Мимика и субтитры считываются **только** из `currentTime` воспроизводимого аудио
- Первый звук стартует до окончания генерации всего ответа
- При деградации сети: лицо замирает, голос продолжается. Не наоборот
- **`[STT]` Микрофон захватывается на протяжении речи персонажа, VAD работает всегда — перебивание голосом должно быть возможно в любой момент**
- **`[STT]` Эхоподавление включено (`getUserMedia({ audio: { echoCancellation: true, noiseSuppression: true } })`). На демо — наушники как гарантия против самоперебивания**
- **`[STT]` Индикатор состояния микрофона: слушаю / говорит персонаж / распознаю. Пользователь должен понимать, слышат ли его**
- Экран методиста после сессии: история разговора, оценка по критериям с цитатами, **`[STT]` кнопка воспроизведения фрагмента под каждой цитатой**, счётчик освобождённых часов

## 9. Приёмочные метрики

| № | Метрика | Порог | Цель |
|---|---|---|---|
| 1 | Time to first audio, p95 | ≤ 3.0 с | ≤ 1.5 с |
| 2 | Смещение аудио и губ | ≤ 200 мс | звук не опережает губы >45 мс, не отстаёт >125 мс |
| 3 | Время остановки при перебивании | ≤ 300 мс | ≤ 150 мс |
| 4 | Возвраты отменённого хвоста | **0** | 0 |
| 5 | Корректно завершённые сценарии | ≥ 4 из 5 | 5 из 5 |
| 6 | Себестоимость минуты | посчитана | ≤ 10 ₽ |

**`[STT]` Где отсчитываются метрики (изменилось):**
- **Метрика 1** — от момента, когда сотрудник **закончил говорить** (VAD endpoint), до первого звука персонажа. Раньше отсчёт шёл от нажатия Enter.
- **Метрика 3** — от **акустического начала речи** пользователя (не от подтверждённого VAD onset) до остановки звука персонажа. Окно подтверждения VAD (2–3 фрейма) съедает часть бюджета — держим его коротким, но не настолько, чтобы ловить эхо.

**Не путать** (теперь три числа): **≤3 с** — до первого звука ответа; **≤300 мс** — на остановку при перебивании; и **VAD endpoint ≈200–500 мс** — задержка распознавания конца реплики, это новый тайминг на входе, не путать с двумя предыдущими.

Порог липсинка асимметричен (ITU-R BT.1359): опережение звука заметно примерно вдвое раньше отставания. Лучше отдать лицо чуть раньше звука, чем позже.

### Бюджет задержки

**`[STT]` Барже-ин (перебивание) — дёшево, потому что локально:**

| Этап | Бюджет |
|---|---|
| VAD onset (клиент, подтверждение 2–3 фрейма) | 50–150 мс |
| Локальная остановка (`pause` + сброс буферов) | < 20 мс |
| **Итого до тишины** | **≈70–170 мс** — укладываемся в цель 150 мс |

**Ответ персонажа (сотрудник договорил → первый звук):**

| Этап | Бюджет |
|---|---|
| **`[STT]` VAD endpoint** | 200–500 мс |
| **`[STT]` STT финализация** (после endpoint, партиалы уже есть) | 100–300 мс |
| LLM: первый токен | 300–800 мс |
| TTS: первый чанк | 150–400 мс |
| Сеть и буфер клиента | 100–200 мс |
| **Итого** | **≈0.85–2.2 с** |

**`[STT]` STT и VAD теперь В бюджете** (при текстовом вводе их не было — это была прямая экономия, которой мы лишились). Порог метрики 1 (≤3 с) держим спокойно; цель (≤1.5 с) стала жёстче из-за endpoint-задержки. Чтобы её защитить: агрессивный/семантический endpointing и спекулятивный старт LLM-prefill на партиалах транскрипта, не дожидаясь финала. Тратим бюджет на вход экономно.

## 10. Технические решения

- **Рендер лица:** Simli (audio→video, managed, ~$0,009/мин, отдаёт чистый API). Запасной вариант для демо без интернета — bitHuman (локально, CPU). Проверить статус SDK: репозиторий переведён в read-only
- **`[STT]` STT:** нужен потоковый API с русским и низкой латентностью финализации. Кандидаты на оценку (проверить актуальные языки/латентность/цены перед выбором): Deepgram (streaming, низкая латентность), Yandex SpeechKit (нативный русский), Google STT. Критерий выбора — качество на числах/ценах/названиях, потому что от этого зависят цитаты в отчёте
- **`[STT]` VAD:** клиентский, лёгкий — Silero VAD (WASM) или WebRTC VAD. Крутится в браузере, решение принимает локально ради barge-in <300 мс
- **`[STT]` AEC:** встроенное эхоподавление браузера (`echoCancellation: true`) как база; наушники — гарантия на демо. Опционально: приглушать/поднимать порог VAD во время известного воспроизведения TTS, чтобы не ловить собственный голос персонажа
- **Не брать:** HeyGen LiveAvatar (латентность 1–2 с, проваливает метрику 1), MuseTalk (высокий риск, русского нет в заявленных языках). Tavus — только рендер, его Raven и Sparrow дублируют наш оркестратор
- **Разбиение для TTS:** по предложениям, первое отправляется сразу, не дожидаясь конца генерации
- **Хранение:** сессии и отчёты в БД с первого дня — нужны для истории методисту и для аналитики. **`[STT]` Дополнительно храним короткие аудио-сегменты реплик пользователя (или полное аудио сессии с индексом по ходам) — под воспроизведение цитат в отчёте. Фиксируем retention и согласие в UI**

## 11. Definition of done для демо

Пять минут, вживую, без записи:

1. Методист выбирает шаблон, меняет два поля, запускает — за минуту
2. Сотрудник проходит диалог **голосом**: быстрый старт звука персонажа, губы за аудио, субтитры не убегают, распознавание речи попадает в лог
3. **`[STT]` Перебить персонажа голосом 2–3 раза, говоря поверх него: речь персонажа встаёт за <300 мс, хвост не возвращается, персонаж отвечает на новую реплику. Эхо не вызывает самоперебивания (AEC/наушники работают)**
4. Прогнать тот же сценарий второй раз — персонаж возражает иначе
5. Показать отчёт методисту: история разговора, баллы, цитата под каждым баллом, **`[STT]` воспроизведение фрагмента под цитатой**
6. Показать счётчик освобождённых часов

Прогнать на чужом вайфае, через проектор **`[STT]` и с реальным микрофоном в шумном помещении** до защиты.

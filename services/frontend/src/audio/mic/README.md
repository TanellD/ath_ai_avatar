# Захват микрофона и определение паузы

`useMicCapture.ts` захватывает моно PCM 16 кГц для Soniox/GigaAM.
`PauseDetector.ts` локально завершает уже начатую пользователем PTT-запись после
подтверждённой речи и длинной паузы. Ручное завершение остаётся доступным.

Это ещё не hands-free VAD: микрофон не включается сам, ложный акустический onset
не прерывает ответ аватара, а пороги до полноценного hands-free должны быть
проверены на собственном акустическом корпусе.

## Что уже работает

| Что | Где | Почему именно так |
|---|---|---|
| `getUserMedia` с AEC | `useMicCapture.ts` | микрофон меньше захватывает голос персонажа |
| PCM 16 кГц / 20 мс | `pcm-capture.worklet.js` | единый формат для realtime STT и локального fallback |
| Автозавершение по паузе | `PauseDetector.ts` | не требует удерживать кнопку и работает одинаково с обоими STT |
| Стрим аудио | `useSessionSocket.ts` | ключи STT не попадают в браузер |

## Чего делать не надо

**Не использовать этот детектор для автоматического перебивания.** В PTT
воспроизведение останавливается по явному нажатию «Начать говорить». В будущем
hands-free onset должен сначала создать обратимый candidate/duck, как требует
план Turn Intelligence, а не сразу вызывать `cancelPlayback()`.

**Не считать стартовые пороги универсальными.** Текущие 160 мс подтверждения
речи и 6000 мс тишины — страховочная настройка PoC. Перед hands-free нужны
измерения false/late endpoint на голосах и микрофонах реальных пользователей.

## Подводные камни, известные заранее

- Шум, музыка или очень тихий микрофон могут не дать локальной паузе сработать;
  ручная кнопка завершения поэтому остаётся обязательной.
- Короткая естественная пауза не должна завершать ход; это проверяется тестом,
  а значение 6000 мс затем уточняется на реальных диалогах.
- Время endpoint считается по числу PCM-сэмплов, а не по `setTimeout`, поэтому
  свёрнутая или притормозившая вкладка не искажает акустическую длительность.

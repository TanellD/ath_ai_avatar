# Приёмочные прогоны: диалог целиком, до отчёта

Стенд доводит тренировку до конца — завершения, оценки и сохранённого отчёта —
и снимает то, что можно измерить только на полной дистанции.

## Зачем отдельно от браузерного стенда

`services/frontend/scripts/browser-drive.mjs` меряет клиентские метрики (первый
звук, остановка при перебивании) и шлёт 4–5 реплик. Этого хватает для метрик 1
и 3, но **до завершения сценария такой прогон не доходит по построению**:
`objection_price` — четыре этапа и до 18 ходов, `interview_junior` — три этапа
и до 12. Метрики 4 и 5 и проверка цитат §7 требуют полного диалога.

## Главное в устройстве: реплика выбирается по этапу

Реплика берётся из пула **текущего этапа**, который приходит в событии `action`,
а не по номеру хода. Это не удобство, а условие осмысленности замера: у каждого
этапа свой `completion_criteria` («выяснил поставщика, объём и что не
устраивает»), и если отвечать не по делу, классификатор вернёт `incomplete`,
этап закроется по `max_turns`, а сценарий «пройдёт» формально — то есть проверка
покажет зелёное там, где ничего не проверено.

Автомат ведёт разговор, стенд за ним следует.

## Что измеряется

| | |
|---|---|
| Метрика 4 (§9) | Возвраты отменённого хвоста: `gen_id` каждого `audio_chunk` сверяется с отменёнными поколениями. Порог — ноль |
| Метрика 5 (§9) | Сценарий дошёл до `evaluate`/`finish`, отчёт сохранён |
| Метрика 1 (§9) | Первый звук на каждом ходу — на полной дистанции, где видно рост задержки к концу разговора |
| §7 | Каждая `evidence` ищется в транскрипте **дословно**. Проверяется не заполненность поля, а совпадение текста: без него методист не сверится за десять секунд |

## Запуск

Запускать внутри контейнера gateway: там уже стоит `websockets` и рядом сам
шлюз. Каталог `benchmarks/` в контейнер не монтируется, поэтому скрипт
скармливается через stdin:

```bash
docker compose exec -T gateway sh -c 'cat > /tmp/full_runs.py' < benchmarks/acceptance/full_runs.py
docker compose exec -T gateway sh -c 'python -u /tmp/full_runs.py'
```

С хоста тоже можно, если поставить `httpx` и `websockets`:

```bash
ACCEPTANCE_OUT=data/full_runs.jsonl python benchmarks/acceptance/full_runs.py
```

Переопределяется окружением: `ACCEPTANCE_API`, `ACCEPTANCE_WS`,
`ACCEPTANCE_OUT`, `ACCEPTANCE_AVATAR`, `ACCEPTANCE_RUNS`.

Один прогон занимает 3–7 минут: диалог из 4–12 ходов плюс оценка сильной
моделью. Результат — по строке JSON на прогон в `ACCEPTANCE_OUT`
(по умолчанию `/data/full_runs.jsonl`, он же `./data/` на хосте; не коммитится).

## Что стенд НЕ проверяет

Метрику 3 (остановка при перебивании) снять отсюда нельзя: она измеряется от
момента, когда звук реально слышно в колонках, а это уровень WebAudio. Для неё —
браузерный стенд.
